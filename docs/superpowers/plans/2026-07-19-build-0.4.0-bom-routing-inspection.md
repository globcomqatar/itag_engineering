# Build ITAG-0.4.0 — BOM, Routing, and Inspection Control Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Extend ERPNext's BOM, Routing, and Operation (via the shared BOM Operation child doctype) with revision/engineering fields, add a new Engineering Inspection Plan DocType, and deliver release-readiness validation, BOM comparison, and multi-level/where-used services — per `ITAG_Engineering_Management_Master_Roadmap_v1.0(Approved).md` Section 12.

**Architecture:** Custom fields on three standard ERPNext doctypes (BOM, Routing, BOM Operation — confirmed via source read that BOM.operations and Routing.operations both reference the SAME child doctype "BOM Operation", so hold-point/witness-point/inspection fields are added once, not duplicated) plus one new custom DocType (Engineering Inspection Plan + Inspection Step child table). No new Workflow in this build — BOM/Routing don't get their own state machine here; `release_readiness_status` is a plain Select computed by a validation service, not a workflow. The actual production-blocking release freeze is Build ITAG-0.5.0's job (Engineering Release + Work Order baseline), so this build has no immutability-guard risk of the kind that hit Engineering Drawing/Product Revision in Build 0.3.0.

**Tech Stack:** Frappe v15.115.0 / ERPNext v15.117.0, MariaDB, ruff (flit_core), FrappeTestCase.

## Global Constraints

- No ERPNext or Frappe core file may be modified anywhere in this build.
- **Forward-reference fields must be `Data`, not `Link`.** "Engineering Release" (Build ITAG-0.5.0's own primary DocType) and "Applicable ECO" (Build ITAG-0.6.0's ECR/ECO DocType) do not exist yet. Every custom field named `engineering_release`/`applicable_eco` added in this build must be a plain `Data` field (free-text identifier placeholder), never a `Link` field pointing at a DocType that doesn't exist — a `Link` to a nonexistent DocType would break `bench migrate`. Builds 0.5.0/0.6.0 are expected to either convert these to real Link fields via a patch, or leave them as denormalized text and add their own proper linking mechanism — that decision is explicitly out of this build's scope.
- Ruff config: 110-char lines, tabs, double quotes, `py310` target (already in `pyproject.toml`, do not change).
- All tests use `frappe.tests.utils.FrappeTestCase`, which only rolls back the DB once per test CLASS, not per test method — every test's `setUp` must explicitly (re)establish the exact state it depends on.
- Site under test: `frappedevelopment.localhost`. Bench commands run via:
  `docker exec -u frappe frappe-docker_devcontainer-frappe-1 bash -lc "cd /workspace/development/frappe-bench && <command>"`
- Work happens on git branch `build-0.4.0-bom-routing-inspection` inside `apps/itag_engineering` (already checked out). Commit after each task.
- House convention (per Decision Log #16, confirmed by Builds 0.1.0-0.3.0): custom fields live in `itag_engineering/setup/custom_fields.py` (extend the existing file, do not create a second one), synced via the existing `after_migrate` hook (`itag_engineering.setup.custom_fields.sync_custom_fields`) — already wired in `hooks.py`, do not duplicate the hook registration. New DocTypes/services live at the existing single-level path `itag_engineering/itag_engineering_management/...` (not the doubled `itag_engineering/itag_engineering/itag_engineering_management/...` some briefs' bash snippets show — every prior build's implementer confirmed the real convention is single-level and used it correctly).
- Company scope: single company, "ITAG International Company" — still does not exist on this site (Decision Log #2); nothing may hardcode it. Item/Company records needed for BOM tests must resolve dynamically (`frappe.db.get_value(...)`), matching every prior build's test factories.
- This build has fixed 7 real bugs across Builds 0.2.0/0.3.0, several by explicitly warning implementers about a specific known bug class before they started (Build 0.3.0 Task 5 proactively avoided a repeat of Task 2's workflow desync this way). Each task below carries its own explicit warning where a known risk pattern applies — do not skip these warnings when dispatching implementers.

```python
# Copyright (c) 2026, Globcom Qatar and contributors
# For license information, please see license.txt

import frappe
from frappe import _
from frappe.model.document import Document

RELEASED_STATES = ("Released", "Obsolete")

# Fields a transition into Obsolete (and the state field itself) is allowed
# to change - everything else, including inspection_steps content, must be
# frozen once Released.
POST_RELEASE_ALLOWED_FIELDS = {"release_status", "modified", "modified_by"}


class EngineeringInspectionPlan(Document):
	def validate(self):
		self.validate_immutable_once_released()

	def validate_immutable_once_released(self):
		if self.is_new():
			return
		before = self.get_doc_before_save()
		if not before or before.release_status not in RELEASED_STATES:
			return

		for fieldname in self.meta.get_valid_columns():
			if fieldname in POST_RELEASE_ALLOWED_FIELDS:
				continue
			if self.has_value_changed(fieldname):
				frappe.throw(
					_("{0} cannot be changed once the Inspection Plan is Released.").format(
						self.meta.get_label(fieldname)
					)
				)

		# get_valid_columns() never includes Table fields (inspection_steps
		# is not a real DB column on the parent) - compare serialized child
		# row content directly, the same pattern Build ITAG-0.3.0 Task
		# (final-review fix 1e835bd) established for Product Revision's
		# child-table immutability gap.
		for table_field in self.meta.get_table_fields():
			fieldname = table_field.fieldname
			current_rows = [
				row.as_dict(no_default_fields=True, no_child_table_fields=True)
				for row in (self.get(fieldname) or [])
			]
			previous_rows = [
				row.as_dict(no_default_fields=True, no_child_table_fields=True)
				for row in (before.get(fieldname) or [])
			]
			if current_rows != previous_rows:
				frappe.throw(
					_("{0} cannot be changed once the Inspection Plan is Released.").format(
						self.meta.get_label(fieldname)
					)
				)
```
