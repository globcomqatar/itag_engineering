# Build ITAG-1.0.0 — Production Release and Certification Implementation Plan

> **For agentic workers:** This build is materially different from every prior one — it adds **no new business DocTypes or services**. Its deliverables are final regression evidence, operating procedures, training materials, a cutover checklist, and a certified production deployment. The `subagent-driven-development` skill still applies for tracking (checkbox steps, one task at a time, independent review of each), but "implementation" here mostly means writing procedure documents and running/recording regression evidence, not writing application code. Presumes Build ITAG-0.11.0 is complete and merged — **do not start this build if Build 0.11.0's Task 6 (migration toolkit) was left gated pending a Decision Log entry that was never made; §24.2 requires ALL of ITAG-0.1.0 through ITAG-0.11.0's approved capabilities to be present, and an incomplete migration toolkit is a real gap that must be resolved or formally accepted as a known exception before this build proceeds** (see §24.7's own checklist item "Known issues accepted").

**Goal:** Release the complete, approved application to Production with controlled migration, validated operations, documentation, and support ownership, closing out all 5 phases and all 20 UAT scenarios. Per `ITAG_Engineering_Management_Master_Roadmap_v1.0(Approved).md` Section 24.

**Architecture:** No new code architecture. This build's "artifacts" are: a final regression test run (reusing Build 0.11.0's `test_full_uat_regression.py` against the true release-candidate build), a set of operating-procedure documents (one per roadmap-listed procedure), role-based training materials and completion evidence, a cutover readiness checklist, an executed deployment sequence against Production, and written certification sign-off from the 7 named approvers.

**Tech Stack:** Frappe v15.115.0 / ERPNext v15.117.0, MariaDB, ruff (flit_core), FrappeTestCase — used only to VERIFY the release candidate; no new application code is written by this build under ordinary circumstances (an exception: if Task 1's final regression surfaces a genuine defect, it must be fixed via a proper fix-and-re-review cycle exactly like every prior build's fix cycles — this build does not get a lighter bug-fixing standard just because it's mostly documentation).

## Global Constraints

- No ERPNext or Frappe core file may be modified — this holds even now; a defect found during final regression is fixed in `itag_engineering`, never by patching core.
- **This build cannot be started, and certainly cannot be exited, while any prior build's own exit gate has an unresolved Critical/Important finding or an explicitly gated/incomplete task** (Build 0.11.0's migration toolkit being the one already-flagged example as of this plan being written) — confirm the state of every prior build's final whole-branch review before beginning Task 1, not just assume they all passed cleanly because they're merged into `develop`.
- Ruff config: 110-char lines, tabs, double quotes, `py310` target (only relevant if Task 1 finds and fixes a real defect).
- Site under test for final regression: `frappedevelopment.localhost` (pre-production). Production deployment (Task 5) targets whatever the actual Production site/environment turns out to be — **this does not exist yet as a concrete target anywhere in this plan or the Decision Log**; confirm the real Production site name/environment/credentials with the user before Task 5, rather than assuming `frappedevelopment.localhost` doubles as Production (it almost certainly does not, given the name).
- Work happens on git branch `build-1.0.0-production-release-certification` created from `develop`. This build's branch will contain mostly documentation, not application code — commit each deliverable as it's completed, same discipline as every prior build.
- House convention (Decision Log #16): documentation deliverables for this build (operating procedures, training materials, cutover checklist) belong at bench-root `doc/ITAG_*.md`, matching where `ITAG_Decisions.md` already lives — not inside the app itself, consistent with this bench's established convention of keeping deep planning/process docs at bench-root rather than in-app.
- **No "known bug classes" section for this build in the usual sense** — its own job IS finding and closing out any remaining instance of every bug class every prior build has already fought (workflow-state desync, permission-gate gaps, child-table immutability gaps, Date/Datetime comparison bugs, naive positional diffing, `update_modified` races, test-fixture collisions, missing idempotency guards) via the full regression run. If Task 1's regression finds a genuine NEW instance of any of these, treat it exactly as gravely as Build 0.4.0's final review treated its own findings — this is the last chance to catch it before certification.

## Final Verification (roadmap Section 24.10 — Exit Gate)

`ITAG-1.0.0` is released only when:
1. Final regression passes (Task 1, including the fresh-site install confirmation).
2. UAT is approved (Task 2 — real human sign-off, not just automated test evidence).
3. Migration reconciles (Build 0.11.0's Task 6, and this build's own migration-related steps in §24.7's checklist).
4. Production deployment succeeds (Task 5).
5. Smoke tests pass (part of Task 5's deployment sequence, step 8).
6. No open critical or high-severity defect remains (Task 1's fix-and-re-review cycle, if any defect was found).
7. Support and operating procedures are active (Tasks 3-4).
8. Production certification is signed (Task 7 — genuinely, by the 7 named humans, not simulated).

**This is the last build in the roadmap. Do not begin any further development after this exit gate without new explicit direction — there is no "Build ITAG-1.1.0" implied by anything in the approved roadmap.**
